DocFX documentation deployment

This folder contains documentation guidance and the helper scripts used to build and publish the project's DocFX-generated documentation.

Summary of the current workflow (updated): the documentation deployment is triggered as part of the project's Pack step. When you run the Pack command for the CodersRealm.NmsAmqpClient project (for example via dotnet pack or the Visual Studio Pack action), the repository's packaging targets will invoke script-main-runner.ps1 which in turn invokes the DocFX deployment flow. A separate convenience script (deploy-docs.ps1) is also included for manual runs.

What changed from earlier versions:

  • The Pack step now runs the primary automation (script-main-runner.ps1). You no longer need to run deploy steps only from the top-level repo by default.
  • The scripts still publish into a separate documentation repository (a sibling repo with the gh-pages branch), but invocation and some layout assumptions were simplified.

Architecture & behavior

  • The pack-time runner (script-main-runner.ps1) collects XML documentation from the build output, runs DocFX to generate the static site, and places the generated site into the docs folder of the configured documentation repository.
  • The deployment script clears visible contents in the target docs folder while preserving the target repo's .git folder so history and branch metadata remain intact.
  • The target repository is switched to the gh-pages branch for publishing. The freshly generated files are committed and pushed to the remote gh-pages branch. The publish uses a force push to ensure the published site matches the generated output exactly.
  • After publishing, the script leaves the documentation repository in a clean state (switching back to the default branch) so your workspace remains usable.

Prerequisites

  • PowerShell 7+ (recommended) otherwise you have to modify scripts to work with Windows Powershell
  • Git (configured with credentials to push to the documentation repository)
  • GitHub CLI (to install: winget install GitHub.cli)
  • DocFX CLI available on PATH
  • dotnet SDK (the same SDK you use to build/pack the CodersRealm.NmsAmqpClient project)

Note: Your development machine must be able to run dotnet pack for the CodersRealm.NmsAmqpClient project. The pack process is what triggers the automatic script-main-runner.ps1 invocation.

Local repository layout

The scripts assume a sibling repository layout where the documentation repository is next to the code repository. Example:

<development-root>/
├── NmsAmqpClient/                         <-- this repository (source + packaging targets)
│   ├── src/                               <-- project source tree
│   └── docfx/                             <-- the folder with scripts and docfx.json
└── NmsAmqpClient-Docs/                    <-- documentation repository (target for published docs)
    ├── .git/
    └── Docs/                              <-- GitHub Pages reads from this folder (gh-pages branch)

How to publish

Preferred (automated):

  1. From the CodersRealm.NmsAmqpClient project run the Pack command. Example from the repository root:

    dotnet pack ./src/CodersRealm.NmsAmqpClient/CodersRealm.NmsAmqpClient.csproj -c Release

    The project's pack targets will invoke script-main-runner.ps1 which performs the DocFX generation and deployment.

Manual (developer debugging or one-off):

  1. Build the project and ensure XML documentation files are produced.

  2. From the docfx folder run the convenience script (if present):

    pwsh ./docfx/deploy-docs.ps1

    Note: the manual script may accept parameters (target repo path, branch, etc.). Inspect the script header for supported switches before running.

Safety and important notes

  • The publish operation performs a force push (git push -f) to the gh-pages branch on the documentation repository. This will replace the remote content on that branch. Make sure you have backups or that this is the intended behavior.
  • The scripts configure Git local settings to avoid CRLF/LF conversion issues (they set core.autocrlf and core.safecrlf locally). This prevents DocFX's LF assets from being altered by Git.
  • The scripts include checks to avoid committing when nothing changed.

If you need the documentation published from a CI pipeline instead of locally, call dotnet pack (or the equivalent MSBuild Pack target) inside the CI agent and ensure the CI runner has permissions to push to the documentation repository.
